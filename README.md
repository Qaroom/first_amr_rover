# first_amr_rover

A ROS 1 (Noetic) description and simulation package for **first_amr_rover** — a differential-drive Autonomous Mobile Robot (AMR) intended for indoor / warehouse scenarios.  
The package ships the rover's URDF model, 3D meshes, Gazebo worlds based on the AWS RoboMaker Small Warehouse assets, and launch files for both RViz visualization and Gazebo simulation.

> 🛠️ **Use the `dev2` branch.** The latest version of the project lives on `dev2` — it contains the most up-to-date world (with the added payload station / wall box) and is the branch this README documents. The `main` branch is older.
>
> 🐧 **This package targets ROS 1 Noetic** (Ubuntu 20.04) with classic Gazebo. It is a catkin package — do not try to build it with `colcon` or ROS 2 tooling.

## What's on the rover

The URDF defines a small ground robot with the following hardware:

- **Differential drive** base, controlled in Gazebo via `libgazebo_ros_diff_drive.so` (plugin name: `amr_controller`)
- **Two 2D lidars** — `front_lidar_link` and `back_lidar_link`, each driven by `libgazebo_ros_laser.so`
- **Two cameras** — `front_camera_link` and `back_camera_link`
- **IMU** — `imu_link`

The two lidar scans are fused into a single 360°-style scan at launch time using `ira_laser_tools`'s `laserscan_multi_merger`:

| Input topics | Merged output |
|---|---|
| `/scan0`, `/scan1` | `/scan` (in `base_link` frame) |
|  | `/merged_cloud` (point cloud) |

## Repository layout

| Folder / file | Description |
|---|---|
| `urdf/first_amr_rover.urdf` | The rover's URDF (exported via the SolidWorks URDF Exporter — see `export.log`) |
| `urdf/first_amr_rover.csv` | Joint information from the exporter |
| `meshes/` | STL meshes referenced by the URDF |
| `config/joint_names_first_amr_rover.yaml` | Joint name list generated by the exporter |
| `launch/display.launch` | RViz visualization of the URDF with `joint_state_publisher_gui` |
| `launch/gazebo.launch` | Full Gazebo simulation: spawn rover, load world, merge lidars |
| `gazebo/amr_factory_world.world` | Custom factory-style world |
| `model/` | Gazebo world files (`new_amr.world`, `new_amr_with_drop.world`, …) and the `payload_wall_box` station model added on `dev2` |
| `models/` | AWS RoboMaker warehouse assets (shelves, pallet jack, clutter, walls, roof, ground, lamp, trash can, bucket, …) referenced via `model://` URIs |
| `package.xml` / `CMakeLists.txt` | catkin package manifest and build script |

## Requirements

- **Ubuntu 20.04** + **ROS Noetic**
- Classic **Gazebo** (the version that ships with Noetic, `gazebo_ros_pkgs`)
- The following ROS packages:
  - `roslaunch`, `robot_state_publisher`, `joint_state_publisher_gui`, `rviz`, `gazebo` (declared in `package.xml`)
  - **`ira_laser_tools`** — used by `gazebo.launch` for `laserscan_multi_merger`, but **not** declared in `package.xml` (see Notes below)

Install the standard dependencies:

```bash
sudo apt install ros-noetic-robot-state-publisher \
                 ros-noetic-joint-state-publisher-gui \
                 ros-noetic-rviz \
                 ros-noetic-gazebo-ros-pkgs \
                 ros-noetic-gazebo-ros-control \
                 ros-noetic-tf
```

`ira_laser_tools` does not have an `apt` binary for Noetic; build it from source in your workspace:

```bash
cd ~/catkin_ws/src
git clone https://github.com/iralabdisco/ira_laser_tools.git
```

## Installation

Clone the **`dev2`** branch into the `src/` folder of a catkin workspace and build it:

```bash
cd ~/catkin_ws/src
git clone -b dev2 https://github.com/Qaroom/first_amr_rover.git
cd ~/catkin_ws
catkin_make            # or: catkin build
source devel/setup.bash
```

## Running

Before launching the Gazebo simulation, expose the package's `models/` directory to Gazebo so it can resolve the `model://aws_robomaker_warehouse_*` URIs used by the world files:

```bash
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:$(rospack find first_amr_rover)/models
```

(Add this to your `~/.bashrc` if you want it persisted.)

### RViz visualization

```bash
roslaunch first_amr_rover display.launch
```

Brings up `robot_state_publisher`, `joint_state_publisher_gui` (interactive sliders for the joints) and RViz, with the URDF loaded as `robot_description`.

### Gazebo simulation

```bash
roslaunch first_amr_rover gazebo.launch
```

This launch file:

1. Starts an empty Gazebo world preloaded with `model/new_amr.world` (an AWS RoboMaker warehouse world).
2. Spawns the rover into Gazebo via `gazebo_ros/spawn_model` using `urdf/first_amr_rover.urdf`.
3. Publishes a static TF from `base_link` to `base_footprint`.
4. Runs `laserscan_multi_merger` to fuse `/scan0` and `/scan1` into `/scan`.

To use one of the other worlds (`small_factory_final.sdf`, `new_amr_with_drop.world`, `new_amr_with_drop_2.world`, or `gazebo/amr_factory_world.world`), edit the `world_name` argument in `gazebo.launch` — the file already contains a few commented-out alternatives ready to swap in.

## Notes

- **`urdf.rviz` is referenced but not in the repo.** `display.launch` passes `-d $(find first_amr_rover)/urdf.rviz` to RViz. That file is not committed, so RViz will start with no preconfigured display. Either save your own `urdf.rviz` at the package root or drop the `-d` argument.
- **`ira_laser_tools` is an undeclared dependency.** It is required by `gazebo.launch` but is not listed in `package.xml`. Worth adding it as a `<depend>` once the package is built from source in the workspace.
- **`CMakeLists.txt` only installs `config`, `launch`, `meshes`, `urdf`.** The `gazebo/`, `model/`, and `models/` folders are not copied into the install space, so launch files resolve their paths from the source tree. This works in a devel workspace but will break a pure install workspace — extend the install loop in `CMakeLists.txt` if you need a clean install.
- **`package.xml` metadata is still placeholder.** `author`, `maintainer email`, and the absence of a `LICENSE` file should be filled in. The declared license is `BSD`.
